# @atlas/contracts

Contratos públicos compartilhados entre packages: tipos, interfaces e erros estruturados.

- **Nenhuma dependência** — nem de runtime, nem de outros packages.
- Runtime permitido: apenas classes de erro e constantes triviais (ex.: `LOG_LEVELS`).
- Um contrato só entra aqui quando um segundo package precisa dele; até lá vive no package dono (regra do Project Structure).
- Antes de alterar um contrato, verifique todos os consumidores: `git grep '@atlas/contracts'`.
- `AskResult` e `ConversationTurn` espelham-se deliberadamente (`text`/`reply` + `steps?: readonly ExecutedStep[]`, SPEC-0014; + `learned?: readonly string[]`, SPEC-0020): ao evoluir o resultado de um, avalie se o outro deve acompanhar.
- `Fact.source?: 'user' | 'learned'` e `MemoryService.remember(text, source?)` (SPEC-0020/ADR-0016): proveniência **opcional/aditiva** — distingue fato afirmado pelo usuário de fato proposto pelo Cognitive (Aprendizado). Default `'user'`; chamadores de 1 argumento seguem válidos. `learned?` carrega os candidatos **como dado** (o Cognitive não grava; a borda medeia).
- `MemoryService.remember(text, source?): Promise<{ fact: Fact; created: boolean }>` (SPEC-0022/ADR-0011): mudança **não-aditiva** no **tipo de retorno** (antes `Promise<Fact>`) — sinaliza fato criado × duplicata reconhecida por normalização determinística (helper interno a `@atlas/memory`, não exposto aqui). Todo consumidor do retorno precisa destruturar `{ fact, created }`; membro de interface de contrato exige grep pelo **nome do tipo** (`MemoryService`/`.remember(`) no repo inteiro, não só pelas construtoras — fakes com cast (`as unknown as`) escapam do `typecheck` e só quebram em `pnpm test`. `Fact`/`forget`/`list`/`prompt` inalterados.
- `MemoryService.dedupe(options?: { readonly apply?: boolean }): Promise<DedupeReport>` + `DedupeReport { readonly applied: boolean; readonly groups: readonly DedupeGroup[] }` + `DedupeGroup { readonly survivor: Fact; readonly duplicates: readonly Fact[] }` (SPEC-0023/ADR-0011): membro **aditivo** (não quebra assinatura existente), mas todo implementador/fake de `MemoryService` precisa passar a implementar `dedupe` — confirma o padrão: um método novo numa **interface de contrato** quebra o `typecheck` de fakes tipados diretamente (aqui, só `apps/cli/tests/status.test.ts`); fakes com `as unknown as` (`ask.test.ts`/`chat.test.ts`) seguem escapando do `typecheck`, só `pnpm test` os pega — 3ª+ ocorrência do mesmo padrão desde a SPEC-0017. Adicionar um método a um contrato **já público** não é "promoção de tipo" (regra do ADR-0007/2º consumidor); aqui o fundamento é o Artigo 11 (autoridade exclusiva da Memory) + Artigo 5 (a CLI não acessa `normalize`/`storage` internos). `remember`/`forget`/`list`/`prompt`/`Fact` inalterados.
- `ExecutedStep.denialKind?: 'blocked' | 'declined'` (SPEC-0019/ADR-0015): discriminador **opcional/aditivo** que distingue negação de política/consentimento de falha de Tool. Rotulado **só** pelo Runtime nos dois branches de negação; ausência = falha de Tool. É o dado que o observador do Cognitive lê para decidir replanejar — evita parsear a string `error` (Artigo 4). Manter opcional: código que constrói `ExecutedStep` sem ele segue válido.
- `skill.ts` (SPEC-0025/ADR-0017): `Skill`/`SkillScope`/`SkillDescriptor`/`SkillDraft`/`SkillRegistry`/`SkillBuilder`/`SkillBuildRequest`/`SkillBuildResult` — contratos novos, sem impacto em tipos existentes. `AtlasPlatform` ganha `readonly skills: SkillRegistry` e `readonly skillBuilder: SkillBuilder` — mais um membro novo em `AtlasPlatform` que quebra o `typecheck` só do fake tipado diretamente (`apps/cli/tests/status.test.ts`); fakes com `as unknown as AtlasPlatform` seguem escapando do `typecheck` (4ª+ ocorrência do mesmo padrão desde a SPEC-0017 — ver `LESSONS_LEARNED.md`). `SkillDraft` carrega só os campos que o modelo produz (`name`/`description`/`instructions`/`toolIds`); `id`/`version`/`scope` do `Skill` final são sempre atribuídos deterministicamente pelo Builder, nunca pelo modelo.
- `MemoryCategory = 'fact' | 'episode' | 'project'` + `Fact.category?`/`Fact.subject?` + terceiro parâmetro opcional de `MemoryService.remember(text, source?, options?: { category?; subject? })` + `MemoryService.list(options?: { category? })` (SPEC-0029/ADR-0011, `memory.ts`): tudo **opcional/aditivo** — nenhum chamador de `remember(text)`/`remember(text, source)`/`list()` precisa mudar. 2ª ocorrência (após a SPEC-0026) de mudança de contrato amplamente consumido que **não** dispara o padrão recorrente de quebra de `typecheck` em fakes tipados diretamente. A invariante "memória de projeto exige `subject` válido (e vice-versa)" é imposta dentro de `@atlas/memory`, não neste package — aqui só o formato do dado.
- `MemoryService.prompt(options?: { readonly query?: string; readonly limit?: number }): string | undefined` (SPEC-0030/ADR-0011, `memory.ts`): parâmetro **opcional/aditivo** (antes `prompt()`) — diff limitado à linha de `prompt`, todo chamador `prompt()` existente segue válido; `Fact`/`MemoryCategory`/`remember`/`forget`/`list`/`dedupe`/`search` inalterados. 3ª ocorrência (após SPECs 0026/0029) de mudança de contrato amplamente consumido que **não** dispara o padrão recorrente de quebra de `typecheck` em fakes. A seleção dos fatos por `query`/`limit` é implementada dentro de `@atlas/memory` (Artigo 11); este package só descreve o formato do dado.
- `Plan.skillId?: string` (SPEC-0026/ADR-0018, `execution.ts`): campo **opcional/aditivo**, mesmo molde do `denialKind?` (ADR-0015) — registra a Skill selecionada pelo Planner/modelo para o plano; código que constrói `Plan` sem o campo segue compilando. Por ser opcional (assim como `Planner.instruction(tools, skills?)` e `CognitiveCoreDeps.skillCatalog?` em `@atlas/cognitive`), esta é a primeira mudança de contrato desde a SPEC-0019 a **não** disparar o padrão recorrente de quebrar o `typecheck` de fakes tipados diretamente — confirma que optatividade total evita a cascata, ao contrário dos membros obrigatórios das SPECs 0017/0019/0022/0023/0025.
- `persona.ts` (SPEC-0039/ADR-0020): `Persona.voiceURI?: string` — campo **opcional/aditivo** (Personas embutidas não o setam); novo tipo `PersonaInput` (todos os campos de `Persona` exceto `id`, obrigatórios, salvo `voiceURI?`); `PersonaService` ganha três membros **obrigatórios**: `create(input): Persona`, `update(id, input): Persona`, `delete(id): void`. Confirma de novo o padrão recorrente: membro novo obrigatório numa interface de contrato quebra o `typecheck` de todo fake tipado diretamente como `PersonaService` (aqui, `apps/desktop/tests/core-bridge.test.ts`); fakes com `as unknown as` seguem escapando do `typecheck`, só `pnpm test` os pega. `PersonaStorage` (a porta de persistência) **não** sobe a este package — fica interna a `@atlas/persona`, mesma regra do `MemoryStorage` (ADR-0011).
