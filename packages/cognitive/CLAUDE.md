# @atlas/cognitive

Cognitive Core (Intelligence) — orquestrador do ciclo cognitivo e consumidor do Model Gateway.

- `createCognitiveCore({ gateway, runtime, personaPrompt?, memoryPrompt? })` → `ask(objetivo)`. O `ask` **deixou de ser tiro único** (ADR-0012): passa a **orquestrar** Planejamento + Execução — 1ª `generate()` (prompt composto + instrução do Planner com o catálogo de `runtime.tools()`) → `planner.parse` → se houver `Plan`, `runtime.execute` + `observe` + eventual replanejamento + `generate()` de composição com os resultados; **sem plano, 1 chamada** (como antes, na voz da Persona/memória). `ask` retorna `AskResult { text; steps? }`.
- **Planner** consolidado no package (Project Structure): `createPlanner()` é **puro**, sem gateway — `instruction(tools)` (framing + schema JSON; string vazia sem Tools, preservando o caminho de 1 chamada) e `parse(saída) → Plan | null`. A chamada ao modelo é do Cognitive Core, não do Planner (autoridade estratégica + testabilidade).
- **Observação (Etapa 5 do ciclo cognitivo, ADR-0015)**: `observe(executionResult) → Observation` (`observer.ts`) é uma **função pura/determinística** (mesmo molde do Planner: sem gateway/IO, testável isolada). Regra: `replan` se houver algum passo `ok:false` **sem** `denialKind` (= falha de Tool: Tool lançou, devolveu `ok:false`, ou ferramenta desconhecida, ou contenção-no-uso/TOCTOU da SPEC-0017); `complete` caso contrário (os dois casos rotulados `blocked`/`declined` são **terminais** — replanejar não concede permissão nem reverte um "não" do usuário). O tipo `Observation` é **interno** ao package — não sobe a `@atlas/contracts`.
- O helper interno `runPlanCycle` (compartilhado por `ask` **e** `respond` desde a SPEC-0014) é um **laço com teto fixo embutido = 1 replanejamento** (`REPLAN_BUDGET`): plano → `runtime.execute` → `observe` → se `replan` e há orçamento, nova `generate()` de replanejamento recebendo um **resumo compacto das falhas** (`summarizeFailures`) → `parse` → `execute` → `observe`; senão (complete / orçamento esgotado / replan sem plano) → `generate()` de composição. **Nunca lança, nunca laça infinito.** Os `steps` de `AskResult`/`ConversationTurn` **acumulam os passos de todos os passes**, na ordem — o CLI mostra o retry reusando `renderSteps`, sem código novo.
- Conversa multi-turno como **dado** (ADR-0008): `startConversation()` + `respond(conversation, input)` (função pura). Desde a SPEC-0014, `respond` **também orquestra** Planejamento + Execução, no mesmo padrão de `ask`: 1ª `generate` com a instrução do Planner (inserida como mensagem `system` logo antes do turno do usuário, para que a última mensagem enviada ao modelo continue sendo o input do usuário) → `planner.parse` → sem plano, resposta direta em 1 chamada (comportamento anterior preservado); com plano, `runtime.execute(plan)` + 2ª `generate` de composição. `ConversationTurn` ganha `steps?: readonly ExecutedStep[]` (espelha `AskResult`); quando Tools rodam, a `Conversation` retornada ganha uma mensagem `system` compacta resumindo os passos (nunca exibida ao usuário — dá continuidade ao modelo entre turnos). `respond` continua **função pura** e o Core continua **sem estado**.
- **Aprendizado (Etapa 6 do ciclo cognitivo, ADR-0016/SPEC-0020)**: `createLearner()` (`learner.ts`) é uma **função pura** no mesmo molde do Planner/Observer — `instruction()` (framing de extração + schema JSON de array de strings; instrui a extrair **apenas fatos que o usuário afirmou ou fortemente implicou**, nunca inferidos — Artigo 13) e `parse(saída) → readonly string[]` (0..N textos; teto fixo embutido = **3** por turno; inválido/não-JSON/vazio → `[]`). Tipo **interno** — não sobe a `@atlas/contracts` nem é exportado pelo index. Após a resposta final do turno (com **e** sem plano, em `ask` e `respond`), o `runPlanCycle` faz **+1 `generate()`** dedicada de extração (via `buildLearnMessages(finalText)`; o retorno antecipado do caminho "sem plano" foi eliminado); falha da chamada/parse → sem `learned`, **o turno nunca quebra**. O Cognitive **propõe** os candidatos em `AskResult.learned?`/`ConversationTurn.learned?` e **não grava** (nenhuma porta de escrita em `CognitiveCoreDeps`); quem grava é a borda via `MemoryService`. Os fatos aprendidos **não** entram como mensagem na `Conversation`.
- Depende só de contratos em `@atlas/contracts` (`ModelGateway`/`CognitiveCore`/`Runtime`) — recebe o `runtime` por **injeção** e nunca importa `@atlas/runtime`/`@atlas/tools` (Regra 9). O Cognitive **não executa Tools direto**: só via `runtime.execute`.
- System prompt é **composto** (ADR-0010 + ADR-0011): `personaPrompt` (identidade) + memória (fatos) + `TASK_FRAMING` (tarefa), na ordem identidade → memória → tarefa — `compose(memoryValue) = [personaPrompt, memoryValue, TASK_FRAMING].filter(Boolean).join('\n\n')`. O Cognitive **não conhece os conceitos de Persona nem de Memory**, só recebe strings.
- **Recomposição ao vivo do `memoryPrompt` (SPEC-0021, ADR-0011):** `CognitiveCoreDeps.memoryPrompt` deixou de ser `string?` e passou a ser um **provider síncrono** — `memoryPrompt?: () => string | undefined` (tipo **interno**, não sobe a `@atlas/contracts`). É **amostrado exatamente 1x por turno** no início de `ask` e de `respond` (`const memoryValue = memoryPrompt?.()`); o `systemPrompt` do turno é `compose(memoryValue)`, compartilhado por **todas** as `generate` do turno (planejamento, replanejamento, composição, extração) — determinístico por turno. Só a fatia de memória é recomposta; `personaPrompt` e `TASK_FRAMING` **continuam estáticos**. Em `respond`, o helper puro top-level `withFreshSystemHead(messages, systemPrompt)` **substitui** o conteúdo da primeira mensagem `system` da `Conversation` (ou **insere** uma no topo quando não houver nenhuma) — tanto nas mensagens enviadas ao modelo **quanto** na `Conversation` retornada (fonte única, sem prompt morto); demais mensagens `system` (ex.: os resumos compactos de Tools) ficam intactas. `respond` continua **função pura**; Core sem estado. Fecha o laço de aprendizado **dentro da mesma sessão**: fato gravado no turno N (por `atlas remember` ou pela borda do Aprendizado) entra no `systemPrompt` do turno N+1, sem depender de nova invocação da CLI.
- **Learner vê os fatos conhecidos (SPEC-0021):** `learner.instruction(knownFacts?: string)` — quando o chamador passa os fatos já preservados (o `memoryValue` amostrado do turno), a instrução os lista e pede explicitamente para **não os re-propor**. Supressão da duplicação intra-sessão **por instrução ao modelo, sem garantia determinística** (não é dedup programático); o Artigo 13 (só o afirmado/implicado, nunca o inventado) permanece intacto. O `buildLearnMessages` passa `memoryValue` a `instruction()`.
- Não persiste memória, não gerencia Tasks, não formata personalidade, não decide quando uma Tool é usada além de aprovar o plano (Module Catalog).
