Existe `@atlas/tools` (`createToolRegistry` + Tools puras `clock`/`calc`, sem `requirements`, `calc` sem `eval`; as primeiras Tools com **IO de leitura** — `read_file`/`list_dir` — que declaram `requirements(args) → ActionRequest` (`access: 'read'`) e leem o disco por uma porta injetável `FsReadPort`, default `nodeFsReadPort()`; a Tool de **escrita** — `write_file` (`{ path, content }`, cria/sobrescreve) — que declara `requirements` com `access: 'write'`; e as três Tools novas da SPEC-0013 — `delete_file` (`{ path }`, remove um arquivo, `access: 'delete'`, a única ação irreversível), `mkdir` (`{ path }`, cria diretório recursivamente/idempotente) e `append_file` (`{ path, content }`, acrescenta conteúdo, cria se ausente; ambas `access: 'write'`) — todas sobre a porta injetável `FsWritePort` (`writeFile`/`deleteFile`/`mkdir`/`appendFile`), default `nodeFsWritePort()`; desde a SPEC-0017, `readFile`/`writeFile`/`appendFile` executam internamente o fecho atômico de TOCTOU — `open(O_NOFOLLOW)` → ancoragem de identidade do fd (`fstat`×`stat(realpath)`) → predicado estreito injetado `Verify = (realpath, access) => boolean` (tipo interno, não sobe a `@atlas/contracts`) → opera sobre o fd e fecha; `nodeFsReadPort`/`nodeFsWritePort` recebem `{ verify?, primitives? }` (`verify` default permissivo, `@atlas/core` fia `permissions.isContained`; `primitives` interno para fakes nos testes); `readdir`/`deleteFile`/`mkdir` **não mudam**) e `@atlas/runtime` (`createRuntime({ registry, permissions, confirm })` → `execute(plan)` sequencial com falhas estruturadas que nunca derrubam a execução + `tools()`; por passo com `requirements`, consulta `permissions.evaluate` antes de rodar a Tool — veredicto `allowed` executa; veredicto `confirm` **pausa e aguarda** `confirm.request(requirement)` (`ConfirmPort`, real via `nodeReadlineConfirmPort()` sobre `node:readline`, nunca trava em EOF/não-TTY) — aprovado executa a Tool, recusado vira `ExecutedStep` negado com motivo distinto de bloqueio; qualquer outro veredicto vira `ExecutedStep` negado e a Tool não roda); o modelo produz o plano em JSON (Planner-driven) e o Runtime o executa deterministicamente, com o Model Gateway **intacto**. `atlas ask` mostra um traço compacto das Tools executadas (incluindo passos bloqueados, com o motivo). O contrato do Model Gateway e o `CognitiveCore` vivem em `@atlas/contracts` (ADR-0007). Existe também `@atlas/context` (`createContextService()` → store de sessão em memória que guarda a `Conversation` por sessão; o `atlas chat` usa-o como detentor, ADR-0008/0009; `respond` segue puro). Existe também `@atlas/persona` (`createPersonaService()` → registro de Personas `jarvis`/`neutral`; a identidade da Persona ativa é injetada na geração do Cognitive, ADR-0010; `atlas ask`/`atlas chat` respondem na voz da Persona; `atlas status` a exibe, `atlas chat` a saúda; seleção por `--persona`/`ATLAS_PERSONA`, default `jarvis`). Existe também `@atlas/memory` (`createMemoryService({ storage })` → autoridade de conhecimento persistente; fatos/preferências explícitos guardados atrás de uma porta de storage injetável, adapter JSON default; `memory.prompt()` é injetado na geração do Cognitive, ADR-0011; `atlas remember "<fato>"`/`atlas forget <id>`/`atlas memory list` gerenciam; caminho por `--memory-path`/`ATLAS_MEMORY_PATH`, default `~/.atlas/memory.json`; Memória persistente × Contexto temporário seguem distintos; **desde a SPEC-0022**, `remember` normaliza o texto (`trim`/`toLowerCase`/colapso de `\s+`) e faz no-op idempotente em duplicata — `Promise<{ fact, created }>` sinaliza criado × existente; acervo legado permanece intacto). Existe também `@atlas/permissions` (`createPermissionService({ readRoots, writeRoots, pathResolver? })` → `evaluate(action)` **puro e síncrono** do ponto de vista de decisão; roteia por `access` — `read` contra `readRoots`, `write`/`delete` contra `writeRoots` — julgando por **contenção lexical** (dentro da raiz → `allowed` para `write`, `confirm` para `delete`; fora/vazio → `blocked` com motivo) sobre caminhos **resolvidos por `realpath`** desde a SPEC-0015 (fecha o escape por symlink dentro de uma raiz permitida, limitação conhecida desde o ADR-0013): nova porta injetável síncrona interna `PathResolverPort` (`realpathSync`, default `nodePathResolverPort()` sobre `node:fs`, sem 2º consumidor → não sobe a `@atlas/contracts`); `readRoots`/`writeRoots` resolvidas uma única vez na criação e o alvo a cada `evaluate`, ambos pelo algoritmo do ancestral existente mais profundo (sobe aos pais até achar um segmento existente, recompõe por cima); fail-closed em qualquer erro de resolução ≠ `ENOENT` (nunca lança — no alvo vira `blocked`, numa raiz na criação só aquela raiz fica fail-closed); `evaluate` segue síncrono, Runtime inalterado. Grants de leitura e escrita **independentes**; `confirm` real desde a SPEC-0013 — quem aplica o veredicto (pausar e perguntar) é o Runtime, nunca o Permission Service, que segue puro; ADR-0013; desde a SPEC-0017/ADR-0014, `PermissionService` ganha `isContained(canonicalPath, access): boolean` — método novo, puro/síncrono, sem IO, sem re-resolver caminho, reusando `within()` sobre as raízes já resolvidas — julgado sobre um caminho **já canônico** (o `realpath` que uma porta de IO ancorou num fd), fiado por `@atlas/core` como o `verify` de `@atlas/tools`; é a segunda barreira do fecho atômico de TOCTOU, aplicada no instante do uso, sem duplicar a autoridade de contenção). `config.permissions.readRoots` (default `[cwd]`, override `--allow-read`/`ATLAS_ALLOW_READ`) e `config.permissions.writeRoots` (default `[]` — não escreve sem opt-in explícito, override `--allow-write`/`ATLAS_ALLOW_WRITE`), precedência `flags > env > defaults`, definem as políticas de leitura e escrita. Desde a SPEC-0018 **ambos aceitam múltiplas raízes**: a flag é repetível (`--allow-read A --allow-read B`) e a env é lista por `path.delimiter` (`ATLAS_ALLOW_READ=A:B`); a lista da fonte de maior precedência substitui a inferior por inteiro (sem merge), segmentos vazios são filtrados e fonte que colapsa para vazio cai no default.
