- **[SPEC-0015](../implementation/specs/SPEC-0015-permission-symlink-hardening.md) (Endurecimento de symlink no Permission Service): `Done`** (aprovada pelo humano em 2026-07-17). Fecha a limitação **conhecida e documentada** desde o ADR-0013: um symlink dentro de uma `readRoot`/`writeRoot` legítima apontando para fora do diretório permitido escapava da contenção lexical (path apenas resolvido por `path.resolve`); agora a contenção opera sobre caminhos **reais** (`realpath`), vale igual para `read`/`write`/`delete` (delete é o mais grave, irreversível). `@atlas/permissions` ganha `PathResolverPort` (`realpathSync(path): string`), porta síncrona **interna** ao package (sem 2º consumidor real — não sobe a `@atlas/contracts`, mesmo critério de `FsReadPort`/`FsWritePort`/`ConfirmPort`), com `nodePathResolverPort()` default sobre `node:fs` `realpathSync` (síncrona, não `fs/promises`). `createPermissionService({ readRoots, writeRoots, pathResolver? })` resolve `readRoots`/`writeRoots` **uma única vez, na criação**, e `evaluate(action)` resolve o `path` alvo **a cada chamada** — ambos pelo **algoritmo do ancestral existente mais profundo** (função interna a `permission-service.ts`, não à porta): sobe pelos diretórios pais até o primeiro segmento que existe, resolve o `realpath` desse ancestral e recompõe por cima os segmentos ainda inexistentes — preserva "criar algo novo dentro de uma raiz válida é permitido" (`write_file`/`mkdir`/`append_file`/`delete_file` sobre um path que ainda não existe) sem regressão. **`evaluate` continua síncrono** — **não** virou `Promise`, contrato de `@atlas/contracts` **inalterado**, Runtime **inalterado** (`permissions.evaluate(requirement)` sem `await`, nenhuma linha mudou em `packages/runtime`). **Fail-closed**: qualquer erro de resolução ≠ `ENOENT` (ex.: `EACCES`) nunca lança — no alvo dentro de `evaluate` vira `{ verdict: 'blocked', reason }`; na criação, se **uma** raiz falha, **só aquela** raiz fica fail-closed (nada é considerado contido nela), as demais seguem funcionando, `createPermissionService` **nunca** lança (decisão confirmada com o humano — mais restritivo derrubaria capacidades legítimas não relacionadas ao erro). `Tools`/`@atlas/cognitive`/`apps/cli` **inalterados** — nenhuma flag/env nova, nenhuma mudança de comportamento visível ao usuário exceto o endurecimento em si. **ADR-0013 ganhou nota de atualização** (sem ADR novo). Testes: 12 casos novos com `PathResolverPort` fake (sem disco real) cobrindo symlink escapa/contido, path novo com ancestral dentro/fora da raiz, raiz configurada contendo symlink, raiz inexistente resolvida por ancestral, fail-closed no alvo e na criação, contagem de chamadas à porta provando resolução única das raízes — suíte de `packages/permissions` sobe de 17 para 29 testes. Fora de escopo (documentado): tornar `evaluate` assíncrono, TOCTOU (symlink trocado entre avaliação e uso), cache/memoização da resolução do alvo, múltiplas raízes por invocação, `rmdir`, flag de auto-aprovação de `confirm`.

Não decide estratégia, não chama o Gateway. Depende só de `@atlas/contracts`. Erro: `MemoryError` (`ATLAS_MEMORY`). JSON corrompido → falha alta (não descarta memória).

# Avisos Operacionais (deste ambiente)

- `pnpm add` na raiz do workspace exige a flag `-w`.
- **pnpm 11 não lê mais o campo `pnpm` do `package.json`**: aprovar build de dependências (ex.: `esbuild`, motor do `tsx`) vive em `pnpm-workspace.yaml` (`allowBuilds: { esbuild: true }`). Sem isso, `pnpm install` sai com código 1 (`ERR_PNPM_IGNORED_BUILDS`) e trava scripts do pnpm.
- **Node nativo não roda o fonte**: a convenção de imports `.js` (NodeNext) do repo não é remapeada pelo _type stripping_ do Node; por isso apps rodam via `tsx` (ADR-0005). Ao rodar TS diretamente, use `tsx`, não `node`.
- O proxy de output (RTK) mascara saída/erros; para ver o completo, `rtk proxy <cmd>`; log em `~/Library/Application Support/rtk/tee/`.
- O executor de comandos do harness pode ficar indisponível temporariamente; o usuário pode rodar comandos com o prefixo `!` para destravar verificações.
- Prettier ignora `**/*.md` por design (protege a documentação manuscrita); commits terminam com o trailer `Co-Authored-By` do modelo em uso.

- CLI: `apps/cli` (`@atlas/cli`) — `main.ts` (casca) → `run()` → gateways locais + comandos `status`, `ask` (`commands/ask.ts`), `chat` (`commands/chat.ts` + `gateway/line-reader.ts` + `gateway/confirm-port.ts`), `remember`/`forget`/`memory` (`commands/`). `--memory-path`/`ATLAS_MEMORY_PATH` selecionam o arquivo de memória; `--allow-read`/`ATLAS_ALLOW_READ`/`--allow-write`/`ATLAS_ALLOW_WRITE` selecionam raízes de leitura/escrita; `status` exibe `readRoots`/`writeRoots`. `gateway/steps-trace.ts` (`renderSteps`) é o traço compacto de `steps` compartilhado por `ask`/`chat`.
- Cognitive Core: `packages/cognitive` (`@atlas/cognitive`) — `createCognitiveCore({ gateway, runtime, personaPrompt?, memoryPrompt? })` → `ask(objetivo)` **e** `respond(conversation, input)` **orquestram** Planejamento + Execução no mesmo padrão (retornam `AskResult`/`ConversationTurn` com `steps?`, ADR-0012, nota SPEC-0014) + `startConversation()`; **Planner** consolidado (`createPlanner()` puro: `instruction`/`parse`); system prompt composto (ADR-0010/0011); `respond` segue função pura, Core sem estado (conversa é dado — ADR-0008).
- Planner/Runtime/Tools/Permissions (execução, ADR-0012/0013): `packages/tools` (`@atlas/tools`) — `createToolRegistry` + `createClockTool`/`createCalcTool` (Tools puras, `calc` sem `eval`) + `createReadFileTool`/`createListDirTool` (1º IO, `requirements` + `FsReadPort` injetável) + `createWriteFileTool`/`createDeleteFileTool`/`createMkdirTool`/`createAppendFileTool` (`FsWritePort` injetável; `delete_file` é `access: 'delete'`, único exige `confirm`); `packages/permissions` (`@atlas/permissions`) — `createPermissionService({ readRoots, writeRoots, pathResolver? })` → `evaluate(action)` puro/síncrono, contenção lexical sobre caminhos `realpath` (`delete` produz `confirm`; endurecimento de symlink desde a SPEC-0015); `packages/runtime` (`@atlas/runtime`) — `createRuntime({ registry, permissions, confirm })` → `execute(plan)` (falhas estruturadas, nunca lança; consulta `permissions` por passo com `requirements`; pausa em `confirm` via `ConfirmPort`/`nodeReadlineConfirmPort()`) + `tools()`; Planner vive em `packages/cognitive/src/planner.ts`. Contratos de execução e permissão em `@atlas/contracts`.
- Model Gateway: `packages/model-gateway` (`@atlas/model-gateway`) — `createModelGateway` (seletor) → provedores `fake`/`ollama`/`remote`; `scripts/smoke.ts` para verificação. Contrato vive em `@atlas/contracts` (ADR-0007).
- Context Service: `packages/context` (`@atlas/context`) — `createContextService()` → `openSession/getConversation/updateConversation/closeSession`; store de sessão em memória, não orquestrador (ADR-0009); detentor da `Conversation` que o `atlas chat` usa via `atlas.context`.
- Persona Service: `packages/persona` (`@atlas/persona`) — `createPersonaService()` → `get/has/list` + `systemPrompt(persona)`; registro embutido `jarvis`/`neutral`; identidade injetada na geração do Cognitive, não decide estratégia (ADR-0010).
- Memory Service: `packages/memory` (`@atlas/memory`) — `createMemoryService({ storage })` → `remember/forget/list/prompt`; porta injetável `MemoryStorage` (`createFileMemoryStorage` default + fake nos testes); `prompt()` injetado na geração do Cognitive; autoridade de persistência, não decide estratégia (ADR-0011). CLI: `remember`/`forget`/`memory list` (`commands/`).
